# 최종전 학습 속도 개선과 게임 속도 조정 (2026-11-17)

대상: 10단계 최종전(티거 1 대 셔먼 3 + T-34 3, 360m 맵, 180초, 7개체 독립 PPO).
측정 PC: i5-12400F(6코어/12스레드), Godot 4.3 내보낸 실행 파일, PyTorch CPU.
측정 원자료: [`docs/perf_2026-11-17/`](perf_2026-11-17/) (경기별 시간, Godot 구간별 시간, 끝 상태 해시).

  다른 학습이 돌지 않을 때 다시 해야 한다(측정 후반에 다른 학습 8개 프로세스가 같은 PC 에서 시작되어
  `contended_*` 파일은 비교용으로만 남겼다: 같은 조건에서 무작위 1.82×, 정책 1.44×).
- 학습된 정책으로 움직이면 Godot 비용이 무작위 행동의 약 2배다(전차끼리·벽과의 충돌 계산, 조준경 시점).

## 어디가 느렸나 (이전, 무작위 행동 180초 1경기 ≈ 12.5초)

Godot 쪽 구간별 시간(`result.perf`, 이제 모든 에피소드 결과와 에피소드 파일에 기록된다):

| 구간 | 이전 | 이후 | 내용 |
|---|---:|---:|---|
| 관측 전송 | 3.7s | 0.28s | 매 결정마다 관측 라벨 389개 문자열을 새로 만들고 있었다 → 한 번만 생성 |
| 지면 추적 | 1.8s | 0.23s | 전차마다 매 틱 레이 16개 → 평탄 지형에서 주변 장애물이 없으면 레이 생략(같은 높이) |
| 전차 물리(지면 제외) | 1.7s | 1.5s | 모듈 상태 조회가 매번 모든 모듈을 훑음 → 종류별 목록 미리 생성 |
| 관측(시야·화면격자·소리·자기상태) | 3.9s | 3.7s | 전투불능 전차 관측은 건너뜀(아무도 쓰지 않음) |
| Python 대기 | 0.3s | 0.25s | |

실제 학습 루프(Python 프로파일, 이전): Godot 대기 68%, 개체별 추론 18%(7회 × 0.36ms/결정), PPO 갱신 7%(갱신 1회 0.055초).
Godot 프로세스가 1개뿐이라 CPU 대부분이 놀고 있었다.

## 바뀐 것

### 1. 시뮬레이션 경량화 (결과 동일)
- `TankPerception.labels()/size()` 캐시.
- `HillMap.flat_height` + `ground_clear()`: 지형 격자가 완전히 평평하면 전차 주변 상자 안에 지형 외 충돌체가
  있는지 한 번만 질의하고, 없으면 16개 지면 레이와 단차 레이 2개를 생략한다. 장애물 근처·경사 지형은 기존 레이 그대로.
- `TankDamageState._kind_ids`: 모듈 종류별 id 목록.
- 전투불능 전차의 관측 갱신 생략.
- 구간별 계측(`perf_summary`)을 에피소드 결과에 기록. 계측 비용은 측정 잡음 수준(약 1.5%).

### 2. 여러 전장 병렬 학습 (`train_individuals.py --n-envs N`, 대시보드 기본 4)
- 전장마다 Godot 1개가 병렬로 돌고, 개체(모델)마다 살아 있는 전장의 관측을 모아 한 번에 추론한다
  (배치 6 추론 0.28ms ≈ 배치 1 의 1.3배 비용).
- 모델·optimizer·버퍼는 여전히 7개로 분리. 경험은 (전장, 개체)별 연속 구간으로 모아 버퍼가 찰 때 전장 순서로
  이어 붙인다. 중간에서 잘린 구간은 다음 상태 가치를 보상에 더해 끝낸다(SB3 시간초과 처리와 같은 방식).
  전장 1개에서는 기존 순차 수집과 같은 이득·수익이 나오는 것을 단위 시험으로 확인했다(`tests/test_parallel_collection.py`).
- 가짜 경험으로 채우지 않는다. 전사한 개체는 그 전장이 끝날 때까지 경험을 내지 않는다.
- 경기마다 새 Godot 프로세스를 쓰는 규칙은 유지하되(재현성), 다음 프로세스를 미리 띄워 재시작 대기를 없앴다(`--prefetch`).
- 에피소드 파일은 `episodes/env<전장>/`, progress.csv 의 `env` 열에 전장 번호.

### 3. 게임 속도 조정 (`tankrl/pace.py`, reset 설정 `pace`)
모든 전차에 같은 배율이라 상대 특성(T-34 가장 빠름·후진 나쁨, 셔먼 빠른 포탑, 티거 느린 포탑)은 유지된다.

| 항목 | 원래 | 지금 |
|---|---:|---:|
| 기동(기어 속도·후진·가속·출력) | ×1 | ×1.35 |
| 포탑 선회·포 고저 | ×1 | ×1.5 |
| 탐지 거리 | 1400m 기준 | ×1.5 |
| 탐지 최소 노출 비율 | 0.12 | 0.08 |
| 식별 크기(3인칭 시야 식별 거리) | 18px (약 130m) | 12px (약 200m) |
| 화면 밖 적 기억 | 12초 | 20초 |

- 기동간 조준 흔들림·차체 출렁임 계수는 속도 배율로 나눠, 같은 비율의 속도에서 기동간 사격 난이도가 이전과 같다.
- 설정은 에피소드 파일 `config.pace` 에 남고 재현은 그 값을 쓴다(지금 빌드로 재현 OK 확인).
  설정이 없는 옛 에피소드는 원래 규칙(배율 1)으로 재현된다.
- `pace` 를 모르는 옛 게임 실행 파일로 학습하면 바로 오류를 낸다(`pace_version`).
- 기존 체크포인트로 이어서 학습하면 환경이 바뀐 것이므로 성능이 잠시 흔들릴 수 있다.

## 확인
- Godot 시험: perception, view, map, spawn/destruction, acceleration, tank, trait(46 checks), combat reward, terrain,
  record, sim smoke 모두 실패 0. human UI 시험은 headless 에서 `TrackDetail` 노드(시각 요소)가 없어 멈추는데,
  시각 요소를 만들지 않는 headless 모드의 기존 동작이다.
- Python 시험 40개 통과.

## 남은 후보
- 학습 정책 주행 시 `move_and_collide` 가 전차 물리의 약 40%(호출당 50~77µs). 충돌 형상 단순화는 게임 동작이 바뀌므로 보류.
- 시야 판정(표적당 레이 6개)과 화면 격자(레이 45개)가 관측 시간의 대부분. 갱신 주기를 늘리면 빨라지지만 관측 의미가 바뀐다.
