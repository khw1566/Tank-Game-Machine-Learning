# 전투 자기 대전

현재 포·장갑 및 점진 보상은 [balance v2 안내](BATTLE_BALANCE_V2.md)를 따른다.

기동·사격 단독 과제를 먼저 통과하지 않고 첫 에피소드부터 실제 포탄으로 싸운다.
기존 v1/v4와 별도 커리큘럼이며, 새 실행 이름을 사용한다.

## 학습 순서

1. `battle_flat`: 평지에서 같은 종류 전차끼리 1대1. 공통 정책이 티거·셔먼·T-34를 번갈아 조종한다. 시작 거리·차체 방향·진영을 무작위화한다.
2. `battle_terrain`: 공통 정책과 누적 가중치를 그대로 유지하고 돌벽·헐다운 엄폐물·지형 굴곡을 섞는다. 약 10%는 이전 전투를 복습한다.
3. `battle_roles`: 공통 정책을 전차별로 복사한다. 각 정책은 실제 적 전차와 1대1 및 티거 1대 대 셔먼 3대 + T-34 3대 전투를 번갈아 수행한다. 최종 단계는 자동 종료하지 않고 설정한 스텝만큼 개선한다.

상대와 아군은 최신 고정 스냅숏 70%, 과거 스냅숏 30%에서 고른다. 에피소드 중 상대 가중치를 바꾸지 않는다. 처음 상대도 초기 정책의 고정 복사본이며 규칙 AI로 대체하지 않는다. 상대 풀은 실행별 `opponents/`에 격리된다. 분화하지 않은 전차의 상대 정책은 공통 모델을 쓴다.

PPO가 이전 단계의 오래된 행동 데이터를 재학습하는 방식은 아니다. 모델·optimizer 상태를 이어받고, 과거 정책을 상대 풀로 유지하며, 이전 전투를 다시 수행해 경험을 보충한다.

## 부위 관측과 사격 보상

기본 관측에는 적 종류, 크기, 보이는 비율, 차체 상대각, 포탑 상대각, 이동/격파 여부, 중심점 조준 오차가 이미 있다. 이 정보는 형상 전체나 내부 모듈 상태가 아니다.

새 `--obs=battle`은 기존 상황·포탄 관측 437개 뒤에 부위 관측 168개를 붙인다. 적 슬롯 4개마다 다음 7개 부위를 구분한다.

- 차체 상부, 차체 하부, 포탑, 포방패, 포신, 왼쪽 궤도, 오른쪽 궤도.
- 각 부위: 보임 여부, 화면 좌표 2개, 주포 기준 각도 오차 2개, 보이는 면의 방향 코사인.

실제 장갑 형상에서 보이는 표본점을 고른다. 표적 자체에 가려진 뒷면, 지형·다른 전차·수풀에 가려진 점, 화면 밖 점, 미식별 표적의 부위 정보는 모두 0이다. 적의 내부 승무원·모듈 상태, 장갑 두께, 정확한 거리, 탄도해, 관통 가능 여부를 관측 정답으로 제공하지 않는다. 부위 좌표는 현재 총구 방향 기준 각도이며 탄 낙차나 이동 표적의 선행량은 정책이 학습해야 한다.

balance v2는 승리 +200을 중심으로 명중 +0.2, 관통 +8, 격파 +25, 실제 모듈 손상 +1.5/파괴 +5를 준다. 비관통 품질·근접 빗나감·실패 후 접근은 작은 중간 보상으로 연결하며, 보조 보상 합계는 경기당 +19로 제한한다. 피해를 받은 전차에도 실제 피해 감점이 적용된다. 시간 초과 -35로 보조 보상만 모아 무승부를 반복하는 행동을 억제한다. 상세 조건은 balance v2 안내를 참고한다.

이 관측과 보상은 약점 사격을 학습할 수 있게 하는 기반이다. 특정 부위를 맞혔다는 사실만으로 의도를 입증하지 않는다. 학습 결과는 관통률, 실제 모듈 손상, 피해 교환, 상대 방향별 조준 위치, 승패로 평가해야 한다. 부위 식별의 화면 크기 기준은 기존 전차 식별 기준을 사용하므로 먼 거리의 작은 부위까지 구분하는 정확도는 아직 별도 모델링하지 않는다.

## 공통 단계 진행

자기 대전 승률 80%를 요구하지 않는다. 평지는 최소 200만 결정, 지형은 추가 최소 300만 결정을 수행한다. 이후 모든 배치 × 전차 조합의 최근 40판에서 명중 발생 판수 35%, 관통 발생 판수 15%, 한 팀 전멸로 끝난 판수 25%를 충족해야 다음 단계로 간다. 단계 시간만 채웠다고 강제 승급하지 않는다.

이 기준은 첫 실험을 위한 교전 성립 기준이며 사격·회피 능력을 보증하는 최종 평가가 아니다. 자기 대전 승률, 노출 시간, 차체/포탑 노출, 피격·관통 피해는 진행 기록에 남는다. 어려운 조합이 기준을 못 넘으면 대시보드에서 단계와 기록을 확인한다.

## 실행

프로젝트 루트에서 새로 빌드한 `build/TankGame_battle.exe`를 사용한다. 대시보드의 새 학습 방식 **전투 자기 대전 · 평지 → 지형 → 전차별 분화**를 고르거나 다음 명령을 실행한다.

```powershell
training/python/.venv/Scripts/python.exe training/python/train.py --godot build/TankGame_battle.exe --curriculum battle --tank shared --auto-branch --run BATTLE-2 --n-envs 8 --device auto --timesteps 80000000 --rotate-steps 3000000 --cycles 3
```

같은 실행을 재개할 때는 같은 인자에 `--resume`을 추가한다. 게임 소스가 바뀌면 실행 파일도 다시 빌드한다. `runnable/TankGame.exe`는 이 새 관측을 지원하지 않는 이전 버전이다. 새 정책은 기존 모델 다운로드 없이 시작할 수 있다.

기존 419/437개 입력 모델을 선택적으로 `--init-model`로 초기화하면 새 입력 가중치와 optimizer 모멘트를 0으로 확장한다. 기본은 새 정책이다. 분화 모델은 동일한 공통 모델의 전체 가중치를 이어받으며 각자 optimizer와 진행 상태를 저장한다.

검증: `training/python`에서 `.venv/Scripts/python.exe -m unittest tests.test_battle_curriculum tests.test_input_migration`을 실행한다. 실제 시뮬레이터 검증은 `TANKGAME_GODOT`에 Godot 또는 내보낸 실행 파일 경로를 넣고 `tests.test_battle_env`를 실행한다. 편집기 실행 파일이면 `TANKGAME_PROJECT`도 지정한다.
