# V6 사선 확보 보상 v2 — 2026-11-20

## 해결하려는 문제

V6-1 티거 기록에서 장시간 시간 초과와 지형·장애물 차단 사격이 반복됐다.
V5의 정지 사격 초기값에 비해 엄폐 전장 기동의 학습 신호가 약했고, 추가했던 관통 퍼텐셜은
실제 EXE에 반영되지 않았으며 지형 가림도 검사하지 않았다.

## 적용한 동작

- **사격 기회**: 전차장 눈 대신 주포 높이에서 적 차체/포탑의 조준 가능한 지점까지 raycast한다.
  지형·건물·돌·전차와 수풀 투과율을 검사한다. 관통 확률이 높아도 가려져 있으면 공격 위치 점수가 없다.
- **위치 보상 v2**: 가시 사격 기회 × 관통 확률로 공격·위협 점수를 계산한다.
  매 에피소드 기존 최고보다 좋아진 부분만 지급해 같은 엄폐물을 드나들며 반복 수령하지 못한다.
  v1의 단순 퍼텐셜 차이와 달리 감점 없이 최고 개선만 보상하는 제한된 보조 보상이다.
- **재배치 진행**: 사선이 막히면 보상 계산기만 주변 12/25/50m의 후보 위치를 찾는다.
  이동 경로의 장애물과 경사를 검사하고 가까운 사격 가능 위치를 우선한다.
  후보까지 거리를 이전 최고보다 줄이면 0.4점/m, 에피소드당 최대 20점이다.
  목표는 접근 중 고정하고 도달하거나 상대가 크게 이동할 때만 갱신한다. 전체 예산은 갱신하지 않는다.
- **사선 개방**: 막힌 상태를 경험하고 최소 5m 움직인 뒤 사선을 확보하면 에피소드당 한 번 +8점이다.
- **정체 비용**: 사선이 없는 상태가 10초를 넘으면 초당 −0.1점이다.
- **차단 사격 비용**: 실제 탄착 결과에서 지형·장애물에 막힌 발사에 −0.3점을 더한다.
- **기동 상충 비용**: 사선이 막혀 있을 때 가속과 브레이크를 함께 사용하면
  `−0.2 × 궤도 입력 크기 × 브레이크 × 시간`을 적용한다.

위치는 학습 보상 계산에만 쓰며 정책에 경로·웨이포인트·상대 정답 위치를 제공하지 않는다.
행동을 규칙 AI로 대체하거나 자동 조준/자동 주행시키지 않는다. 750개 관측·11개 행동과 가중치 구조는 유지한다.
기동/위치 보조 보상은 상위 단계에서 기존 position 배율 1.0/0.8/0.5/0.3으로 감소한다.
전력 교환·승패 보상과 승급 조건은 유지한다.

## 학습과 저장

- V6 기본 `gamma=0.999`, `gae_lambda=0.995`. 다른 커리큘럼의 기본은 0.995/0.97이다.
- 현재 `V6-1`에는 `--lr 0.0001`을 적용했다. 명시한 학습률을 재개 모델에도 적용하도록 로딩을 수정했다.
  학습률 생략 시 저장 모델의 값을 유지한다.
- 모델·Adam 상태·누적 스텝을 유지한다. 이전 보상 v1 평가 결과는 `previous_assessments`에 남긴다.
  CSV·경기 JSON은 계속 보존하고 목표 버전 2를 기록해 그래프가 분리되게 한다.
- 보상 변경 전 건강 체크포인트 기준은 intervention 폴더에 보존하고 새 기준으로 시작한다.
  건강 점검에서 승률 하락은 모든 맵에 최근 40판 이상이 쌓인 뒤 판단한다.
  초기에는 빨리 끝나는 승리만 먼저 집계되므로 그 승률을 최고 성적으로 삼지 않는다.
- `hello.v6_tactics_version=1`을 검사한다. 구형 EXE로 새 보상을 조용히 무시하는 실행을 막는다.
- 실행 EXE: `build/TankGame_v6_tactics_v2.exe`. 원래 `build/TankGame_v6.exe`는 그대로 보존했다.

현재 실행은 저장 후 종료한 **5,693,194스텝**에서 동일한 `V6-1` 이름으로 재개했다.
티거·셔먼·T-34의 교대 순서와 2M스텝/차종, 자동 환경 수, 100판 기록·100k스텝 저장을 유지한다.
초당 결정 10Hz와 행동 탐색 방식은 유지한다. 먼저 보상과 장기 신용 할당을 고쳐 기동을 유도하고,
제어 주기나 gSDE까지 동시에 바꿔 원인 분리가 어려워지는 일을 피한다.

## 검증

- Godot 사선/재배치 검사 12개, 기존 공격 보상 20개, 전투 보상 28개 통과.
- Python 79개 검사 통과(환경 의존 4개 skip).
- 새 EXE로 별도 디렉터리에서 원본 체크포인트를 복사해 실제 PPO 16,384스텝 검증.
  업데이트 3,267 → 3,331, 파라미터 변화·유한값·저장/재로딩을 확인했다.
  실제 경기에서 `position`, `fireline_progress`, `fireline_open`, `blocked_shot`,
  `fireline_stall`, `maneuver_conflict` 보상 발생을 확인했다.
- 구형 EXE 시작 거부를 확인했다.
- 새 보상 경기 한 판을 행동 기록으로 재현해 끝 상태 해시 일치를 확인했다.
- 현재 실행에서도 새 보상 발생과 PPO 수집·갱신·체크포인트 저장을 별도로 확인한다.

이 검증은 적용·실행 확인이다. 장기 승률 개선을 입증한 결과는 아니다.

## 고정 평가

`training/python/evaluate_v6_fixed.py`는 5개 맵 × 규칙/고정 모델 상대를 동일 시드로 평가한다.
학습 정책과 상대는 결정론적으로 추론하며 optimizer를 갱신하지 않는다. 체크포인트·상대·EXE 해시를 남긴다.
`--seeds-per-map`을 늘려 평가 표본을 키운다. 비교 시 상대·게임·시드·표본 수를 같게 유지한다.

```powershell
python training/python/evaluate_v6_fixed.py --godot build/TankGame_v6_tactics_v2.exe --model <model.zip> --opponent <frozen_opponent.zip> --out <new_output_directory> --seed 20261120 --seeds-per-map 10
```

적용 전 정책의 10판 예비 기준선은 `output/v6_tactics_validation/fixed_baseline/evaluation.json`에 있다.
이는 학습 중 탐색 승률과 다른 평가이므로 두 값을 직접 비교하지 않는다.
결정론적 평가 승률·시간 초과·차단 사격률을 함께 보고, 학습 경기의 맵별 이동량과 승급 조건도 확인한다.

5.8M스텝 저장본의 같은 10판 예비 비교는 `fixed_after_5800024/evaluation.json`에 있다.
이전/이후 모두 2승이며 시간 초과는 7/8판, 차단 사격 비율은 95.1%/94.1%였다.
약 107k스텝의 짧은 적응 후 결과로, 승률 개선을 확인하지 못했다. 표본도 작으므로 개선·악화의
유의성을 주장하지 않는다. 검증된 것은 새 보상이 실제 학습에 들어간다는 점이다.

이후 같은 맵·시드·상대를 사용한 60판 비교에서 적용 전 5,693,194스텝 모델은 28승과 시간 초과 21판,
12,700,024스텝 모델은 24승과 시간 초과 17판이었다. 차단 사격은 두 모델 모두 약 82.5%였다.
